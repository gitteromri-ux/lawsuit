The agreement, and the breach count against each clause

These are the operating terms set by the client and accepted by the agent. Each card shows how many documented cases breach that specific clause.

RULE 01

Plan before working

A written time budget with phases, cumulative percentages and a minimum 15 percent buffer, posted before the first real tool call.

3 recorded breaches
RULE 02

Pace in numbers

Status reported at 25, 50 and 75 percent of elapsed budget as a single numeric line. Prose status is banned.

5 recorded breaches
RULE 03

Scope is never cut

One hundred percent of the request ships. No deferring, no phase two, no placeholders, no samples.

16 recorded breaches
RULE 04

No extensions, ever

The deadline is fixed input. More time is never requested under any circumstance.

0 recorded breaches
RULE 05

Audit before saying done

Every link opened, every file viewed, every number recomputed, before the word done is used.

38 recorded breaches
RULE 06

Recovery repaid in speed

A miss triggers 2x throughput on the remaining work through parallelism, never through reduced scope or reduced audit.

20 recorded breaches
RULE 07

Zero friction handoff

Direct deep link plus exact copy paste text, pre-sized to the field limit. Navigation directions are a service failure.

3 recorded breaches
RULE 08

Do not waste billed compute

Third party tools where they are faster. No sequential execution of parallel work. No loops repeating a failed output.

Method, and what this record cannot prove

How it was built. Every stored conversation transcript on the account was read end to end, 40 sessions covering 2026-07-20 to 2026-08-07. Each agent commitment was traced forward to find out whether it was met. A case is only recorded when the supporting text exists in the transcript.
LIMIT 01

History depth

The account stores sessions back to 2026-07-20. Anything before that date is not retained and is therefore absent from this record. No case here is inferred from a session that could not be opened.

LIMIT 02

Credit accounting

A per task billing ledger is not exposed on this account, so no case claims a specific credit amount. What is recorded instead is measurable waste: re-runs caused by agent defects, sequential execution where parallel was instructed, and loops repeating a rejected output.

LIMIT 03

Proven against alleged

66 cases are marked proven, meaning both the commitment and its contradiction are quoted from the same transcript. 23 are marked alleged, meaning the client asserted the failure and the transcript carries no confirming admission. The distinction is kept deliberately, because a record that overstates gets dismissed.

METHOD 05

Machine verified quotes

Every quote on this site was checked character by character against the stored transcript by the build script. 143 quotes were checked. 0 could not be matched and were deleted rather than published, and 0 cases were downgraded from proven to alleged as a result. 79 of 89 cases carry fully matched quotes.

LIMIT 04

Intent

Nothing here establishes intent. The record documents what was promised, what was delivered, and the gap between them. Characterising that gap is a separate judgement and is left to the reader.
